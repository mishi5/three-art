# #254 ノード定義文言の i18n 化（キー化カタログ・#244 第2弾）設計

Issue: https://github.com/mishi5/three-art/issues/254

## 方針（ユーザ決定: 方式A＝キー化カタログ）

- ノード定義（`NodeTypeDef`）内の日本語直書き description を**明示的なカタログキー**に置き換え、
  `{ key: { ja, en } }` のカタログへ集約する。日本語文字列をキーにした暗黙辞書（案B）は不採用。
- ja は**現行文言を一字一句そのまま**カタログへ移設（既定言語 ja の表示は従来と同一＝後方互換）。
- en は全キーに付与（English 切替でツールチップ・ノード追加パネル・`getNodeCatalog()` が英語になる）。

## キー命名規約

- ノード説明: `node.<Type>.desc`（例: `node.Sine.desc`）
- ポート説明: `node.<Type>.port.<portId>`（例: `node.Sine.port.t`）
  - 入出力で同 id・別説明の場合のみ出力側へ `.out` を付ける（例: `node.PointTransform.port.points.out`）
- param 説明: `node.<Type>.param.<paramId>`（例: `node.Sine.param.freq`）
- 複数ノードで共有される定義（共有モジュール内の PortDef/ParamDef）は `node.common.<領域>.<id>`:
  - `nodes/audio-feature-logic.ts` → `node.common.audioFeature.*`（signal/volume/bass/mid/treble/trigger/onsetThreshold/onsetCooldown）
  - `graph/audio-signal.ts` → `node.common.audioSignal.audio`
  - `nodes/effect-bypass.ts` → `node.common.effect.enabled`
  - `nodes/video-fade-logic.ts` → `node.common.video.fade`
- label は全ノードで英語のみ（走査で日本語 label ゼロを確認）のため翻訳対象外。enum options も英語トークンのため対象外。

## 構成

- **`i18n-nodes.ts`（新規）**: ノード文言カタログ `NODE_CATALOG`（342 キー）。`i18n.ts` の肥大を防ぐため分離。
  `i18n.ts` の `Catalog` 型のみ import（値の循環参照なし）。
- **`i18n.ts`**: `MERGED_CATALOG = { ...CATALOG, ...NODE_CATALOG }` を持ち、
  - `MsgKey` を `keyof CATALOG | keyof NODE_CATALOG` に拡張（既存 API を壊さない）
  - `t()` は MERGED から解決
  - **`resolveNodeText(text)`（新規）**: カタログにあれば現在言語で解決、無ければそのまま返す
    （未キー化の残存文言・動的文字列・テスト用フェイク定義でも表示が壊れない）。
- **`NodeTypeDef` は型変更なし**: `description?: string` にキー文字列を保持し、表示点で解決する。

## 表示点（すべて resolveNodeText 経由）

| 表示点 | ファイル | 内容 |
| --- | --- | --- |
| ノード/param/ポートのホバーツールチップ | `editor/tooltip.ts` `tooltipForHit()` | body を解決 |
| ノード追加メニューのツールチップ (#203) | `editor/tooltip.ts` `nodeMenuTooltipContent()` | body を解決 |
| ノード追加パネルの説明行 | `editor/node-add-panel.ts` `buildNodeAddSections()` | items[].description を解決 |
| AI 向けノードカタログ | `api/ai-api.ts` `buildNodeCatalog()` | def/port/param の description を**呼び出し時点の言語**で解決して返す |

layout.ts / param-overlay.ts は description を表示しない（param 行は label のみ）ため対象外。

## 動的 description の扱い

テンプレートリテラルで生成していた 18 箇所はキーのテンプレートに置換:

- `TextureSequencerNode.ts`: `` `node.TextureSequencer.port.tex${i + 1}` ``（tex1〜tex8 をカタログに列挙）
- `AudioMixNode.ts`: `` `node.AudioMix.port.in${i + 1}` `` / `` `node.AudioMix.param.level${i + 1}` ``
- `TapSequencerNode.ts` / `GraphVisualNode.ts`: 文字列連結の desc を単一キーに置換

## 網羅テスト（`i18n-nodes.test.ts`）

registry（`createDefaultRegistry()`）を走査して自動検証する:

1. 全ノードの desc/port/param の description 値がカタログのキーであること（キー漏れ検出。例外リスト `EXCEPTIONS` あり・現状空）
2. カタログの全キーがいずれかの定義から参照されていること（死にキー検出）
3. 全エントリが `node.` 始まりで ja / en とも非空であること（訳漏れ検出）
4. `resolveNodeText` の言語切替・未知文字列パススルー・`t()` からの解決

新ノード追加時に description をキー化し忘れる／カタログへ ja・en を足し忘れると 1〜3 が fail する。

## 既存テストへの影響

tooltip / node-add-panel / ai-api の既存テストはフェイク定義（生の日本語 description）を使うが、
resolveNodeText がカタログ未登録文字列をそのまま返すため無変更でパスする。
