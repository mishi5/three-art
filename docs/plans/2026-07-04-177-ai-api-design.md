# #177 AI 操作インターフェース（サーバレス）設計 ADR

Issue: https://github.com/mishi5/three-art/issues/177

## ステータス

採用（v1 実装済み）

## コンテキスト

AI（外部エージェント / LLM / スクリプト）から node-vj を操作したい。サーバ側には
できるだけ機能を持たせず、フロント側で完結（サーバレス）させる。操作対象は
「グラフの読取・宣言的な丸ごと差し替え・パラメータ変更・シーン切替・評価スナップショット取得」。

## 決定

v1 は次の 2 経路を実装する。

1. **`window.nodeVj.api`**: 型付きコマンド API（`createAiApi(hooks)`）。
   既存の debug 用 `window.nodeVj = { graph, registry, runtime, editor, sceneManager, recorder }`
   はそのまま残し、`api` を追加する。ブラウザコンソール・ブックマークレット・拡張の
   content script から直接呼べる。
2. **postMessage 受け口**: `window.postMessage` で JSON コマンドを受け、結果を送信元へ返信する
   （`installPostMessageBridge(api)`）。**同一オリジン限定**・**常時有効**（opt-in 不要）。

コマンド設計は**宣言的**を主軸とする（グラフ YAML の丸ごと差し替え＝既存 serialize の往復）。
命令的 API は最小限（`setParam` / `switchScene`）に絞る。ノード単位の addNode/connect は
YAML 差し替えで表現できるため v1 では持たない。

### 経路の選択肢と却下案

| 経路 | 判断 | 理由 |
| --- | --- | --- |
| `window.nodeVj.api`（グローバル関数群） | **採用** | 実装が最小・型が付く・コンソール/拡張から即使える。サーバ不要 |
| `window.postMessage` 受け口 | **採用** | 別コンテキスト（iframe 親子・拡張・自動化ツール）から JSON だけで操作できる。オリジン検査で境界を引ける |
| WebSocket ブリッジ（フロントが AI 側サーバへクライアント接続） | **v2 送り** | ブラウザ外のプロセス（CLI の LLM エージェント等）から直接叩ける唯一の経路だが、中継サーバの起動・接続管理・再接続が必要でスコープが大きい。v1 の API サーフェスをそのまま `{ cmd, args }` で流せるよう postMessage とプロトコルを共有する設計にしてある |
| ブックマークレット専用口 | **却下** | `window.nodeVj.api` があればブックマークレットは単なる呼び出し側にすぎず、専用実装が不要 |
| ローカル軽量ブリッジ（ネイティブアプリ） | **却下** | サーバレス方針に反する。WebSocket 案（v2）で吸収する |

### セキュリティ

- **same-origin 限定**: `event.origin !== location.origin` のメッセージは無視する。
  別オリジンのページ / iframe からは操作できない。
- **常時有効の判断**: node-vj はローカル実行前提の VJ ツールで、秘匿情報を持たず、
  同一オリジンのコードは postMessage を使わずとも `window.nodeVj` を直接触れる
  （同一オリジン＝同権限）。よって opt-in ゲートを設けても攻撃面は減らない。
  常時有効にして AI からの接続手順を最小化する。
- 書込系は既存の検証（deserializeGraph のサニタイズ・addConnection の型/循環検査・
  param の kind/範囲検証）を必ず通す。不正入力は `{ ok: false, error }` に落ち、
  ワークスペースを壊さない。
- `applyGraphYaml` は History に積むため、AI の誤操作は Cmd+Z で戻せる。

### アンドゥ（History 連携）

- `applyGraphYaml`: 適用**直前**に `history.record(graph)`。preset 読込 UI は
  `history.clear()`（ワークスペース置換扱い）だが、AI 適用は対話的な編集の一種なので
  **undo 可能**にする（Cmd+Z で差し替え前へ戻る）。
- `setParam`: スライダー編集と同じく変更直前に `history.record`。値が変わらないときは
  記録しない（`NodeEditor.editParam` の onCommit と同じ挙動）。
- `switchScene`: シーンパネルの切替と同一経路（`sceneActions.switchTo`）。履歴はシーン別
  トラックのため記録不要（既存挙動どおり）。

## 実装

```
src/apps/node-vj/api/
├── ai-api.ts                  … コマンド実装。main.ts から依存をフック注入（AiApiHooks）
├── ai-api.test.ts
├── post-message-bridge.ts     … プロトコル検証（純関数）＋ dispatch ＋ リスナ設置
└── post-message-bridge.test.ts
```

- `createAiApi(hooks)`: graph / registry / history / runtime.getOutputs / シーン操作 /
  YAML 適用関数（main.ts の既存クロージャ）を注入。`graph-io-controls` の
  `ProjectIoHooks` や settings-panel の actions と同じ「main が配線・モジュールは薄い」構成。
- main.ts 末尾で `window.nodeVj.api` に載せ、`installPostMessageBridge(aiApi)` を呼ぶ。
- `applyYaml` フックは preset 読込（`mountGraphPresetControls` の applyYaml）と同じ経路
  （deserializeGraph → replaceGraph → ensureStates → restoreAssets）を再利用し、
  履歴のみ record に変える。`maybeAutoStopCamera()` も呼ぶ（#214）。

## API リファレンス（AI に渡せる仕様）

すべての結果は JSON シリアライズ可能。失敗は常に `{ ok: false, error: string }`。

### 読取

| cmd / メソッド | args | 結果 |
| --- | --- | --- |
| `getGraphYaml()` | なし | `{ ok: true, yaml: string }` — 編集中グラフの YAML（`applyGraphYaml` にそのまま渡せる） |
| `getScenes()` | なし | `{ ok: true, scenes: [{ id, name, active, output }] }` — `output` は実効出力（ピン無し＝編集追従時はアクティブシーンが出力扱い） |
| `getNodeCatalog()` | なし | `{ ok: true, version: 1, nodes: [{ type, category?, description?, inputs: [{ id, type, label, description? }], outputs: […], params: [{ id, label, kind, default, min?, max?, step?, options?, description? }] }] }` — `inputs` は接続検証と同じ実効入力ポート（数値 param 由来の入力を含む）。`version` はグラフ YAML に書く `version` の値 |
| `getStatus()` | なし | `{ ok: true, activeSceneId, outputSceneId, nodeCount, nodes: [{ id, type, outputs: { <port>: number\|boolean\|string } }] }` — 直近評価値のスナップショット。プリミティブはそのまま、texture 等のオブジェクトは `"<Texture>"` のような型名。`outputSceneId` は実効出力シーン id |

### 書込

| cmd / メソッド | args | 結果 |
| --- | --- | --- |
| `applyGraphYaml(yaml)` | `{ yaml: string }` | `{ ok: true, warnings: string[] }` — deserializeGraph で検証（未知ノード / 不正接続は除去して warnings）。History に積むので Cmd+Z で戻せる。YAML 不正 / version 不一致は `ok: false`（グラフは無傷） |
| `setParam(nodeId, paramId, value)` | `{ nodeId, paramId, value }` | `{ ok: true }` — kind を検証（number/int は min/max クランプ・int は丸め・enum は options 検証・boolean/string は型一致）。ノード / param 不在はエラー |
| `switchScene(sceneId)` | `{ sceneId }` | `{ ok: true }` — シーンパネルと同じ切替経路。不在 id はエラー |

### postMessage プロトコル

- 受信: `{ type: "node-vj:cmd", id: string, cmd: string, args?: object }`
- 返信: `{ type: "node-vj:result", id, result }` を `event.source`（無ければ window 自身）へ
  `targetOrigin: event.origin` で送る。
- `type` が `"node-vj:cmd"` 以外は無視（他ライブラリの postMessage と衝突しない）。
  `type` が合うのに `id` / `cmd` / `args` の形が不正なものはエラー返信。
- 別オリジンからのメッセージは（type が合っていても）無視。

呼び出し例（同一タブのコンソール）:

```js
// 型付き API
nodeVj.api.getNodeCatalog();
nodeVj.api.setParam("speed", "value", 0.8);
const { yaml } = nodeVj.api.getGraphYaml();
nodeVj.api.applyGraphYaml(yaml); // 往復

// postMessage 往復
window.addEventListener("message", (e) => {
  if (e.data?.type === "node-vj:result") console.log("result:", e.data.id, e.data.result);
});
window.postMessage({ type: "node-vj:cmd", id: "1", cmd: "getStatus" }, location.origin);
```

## v2（スコープ外・将来案）

- **WebSocket ブリッジ**: フロントが `ws://localhost:<port>` の中継サーバ（機能を持たない
  純パイプ）へクライアント接続し、`{ id, cmd, args }` / `{ id, result }` をそのまま流す。
  プロトコルは postMessage と共通のため、`dispatchCommand(api, cmd, args)` を再利用するだけで
  実装できる。接続 UI（接続先・自動再接続・接続中表示）が主なスコープ。
- 命令的パッチ API（addNode / connect / removeNode）: YAML 差し替えで代替できているが、
  大きいグラフでの差分編集が増えたら検討。
- `getStatus` の購読版（変化 push）: ポーリングで足りなくなったら検討。
