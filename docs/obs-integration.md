# OBS 連携（NDI 代替の仮想カメラ導線）

Issue: https://github.com/mishi5/three-art/issues/283 （親: #274）

node-vj のライブ出力を OBS に取り込み、OBS の仮想カメラや配信・録画に流すための手順。
**推奨方式は「出力ウィンドウ（#148）の ウィンドウキャプチャ」**——エンコードを一切経由しないため
無劣化・60fps・低負荷で、追加の設定やコードを必要としない。

## 手順

1. **node-vj を起動**して、ツールバーの外部出力ボタンで**出力ウィンドウ**を開く
   （出力ウィンドウはクリックで全画面化できるが、OBS 取り込みではウィンドウのままでよい）。
2. **OBS でソースを追加** → 「**macOS スクリーンキャプチャ**」（または「ウィンドウキャプチャ」）
   → 方式を「ウィンドウキャプチャ」にし、対象に **node-vj の出力ウィンドウ**を選択。
3. 出力ウィンドウの黒帯（レターボックス）が入る場合は、OBS 側でソースを右クリック →
   「変換」→「画面に合わせる」やクロップで調整する。
4. **音声**: OBS の「音声入力キャプチャ」等でデスクトップ音声を拾うか、macOS スクリーン
   キャプチャの音声キャプチャ機能（対応バージョンの場合）を使う。node-vj 側はグラフに
   AudioOutput があれば通常のシステム音声として再生されている。
5. **仮想カメラとして使う場合**: OBS の「仮想カメラ開始」→ Zoom/Meet 等の入力デバイスで
   「OBS Virtual Camera」を選択。

## 注意点

- **出力ウィンドウは最小化しない**（macOS のウィンドウキャプチャは、他のウィンドウの裏に
  隠れていてもキャプチャできるが、最小化・Dock 収納中は更新されない）。
- 出力ウィンドウの表示中はレンダリング解像度が 1920×1080 に引き上げられる（#148）。
  OBS 側の基準（キャンバス）解像度も 1920×1080 にしておくと等倍で取り込める。
- シーン切替（#174）をしても、出力ウィンドウは「出力シーン」の最終ミックスを映し続ける。

## なぜウィンドウキャプチャ推奨か（WebRTC 方式の取り下げ経緯）

当初、OBS のブラウザソースへ WebRTC でミラー配信する「クリーンフィードページ」方式を実装した
（PR #288・取り下げ）。シグナリングの WS リレー化・H.264 ハードウェアエンコード優先化まで行い
1080p 維持は達成したが、`canvas → キャプチャ → エンコード → デコード → ブラウザソース描画` と
不可逆圧縮を挟むパイプラインである以上、fps・画質ともウィンドウキャプチャ（無劣化・直接取得）
に届かず、同一マシンでの取り込み用途では構造的に不利と判断した。

実装はブランチ `feature/283-clean-feed` に保存してある。ウィンドウキャプチャで対応できない
「**別マシンへのネットワーク越し配信**」が将来必要になった場合は、このブランチが土台になる
（WebRTC 自体はネットワーク配信にこそ適する）。
